# Опросник: чем искать по конфигурации

Этот файл — указание агенту. Его цель: человек выбрал, чем ты ищешь по конфигурации сверх карты и `rg` из части 3, а выбранное собрано и проверено на задаче человека. Ставишь всё по правилам части 1: по одной вещи, из источника, названного ниже, после «да». Конфигурацию и расширения базы не меняешь ни в одном варианте.

Ответы и выбор записывай в `setup-log.md`, раздел `## Индексация`.

## Вопросы

Задавай по одному, своими словами. Где ответ можно узнать самому, узнай и скажи человеку.

1. **Какие задачи.** Обработки и отчёты по нескольким известным объектам; доработки, где надо найти все места использования; вопросы по смыслу («где считается себестоимость»); разбор чужого кода.
2. **Размер конфигурации.** Посчитай сам: число объектов из строки `Карта: …`, файлы и мегабайты из строки `Выгружено …`. Назови человеку.
3. **Машина.** Свободная память и Docker — из описи (`inventory.ps1`). Спроси, сколько места на диске можно отдать под индекс.
4. **Путь из части 1.** «Unica», «Свои инструменты» или «Своя связка» — из `setup-log.md`.
5. **Как часто меняется конфигурация.** Каждый новый релиз — это обновление выгрузки, а любой индекс поверх неё надо перестраивать.

## Б. Поиск Unica

Источник: github.com/IngvarConsulting/unica, описание инструмента `unica.search` в самой Unica. Работает только в пути «Unica».

**Unica 0.13 общую выгрузку вне проекта не принимает (проверено 09.11); работает, только если выгрузка внутри проекта, а набор так не делает.** 09.11 Unica отказала и по прямому пути к `xml\`, и через ссылку-junction из папки проекта: «sourceDir must be inside workspace root». Если человек всё же выбрал Б, предупреди его об этом до правки `v8project.yaml`.

1. В `v8project.yaml` добавь набор исходников с выгрузкой конфигурации, после «да»:

   ```yaml
     - name: config
       type: CONFIGURATION
       path: '<путь configDump>\xml'
   ```

2. До первого поиска узнай, пишет ли Unica что-нибудь в каталог набора: сравни список файлов `xml\` верхнего уровня до и после первого `unica.search`. Если появились новые файлы или папки, остановись и скажи человеку: в каталог выгрузки пишет только `dump-config.ps1`.
3. Для набора `config` разрешены только `unica.search` и `unica.view`. Не вызывай для него `pull`, `push` и `make`: `pull` заменит выгрузку, `push` загрузит конфигурацию в базу.
4. Проверка: `unica.search` с `corpus: "names"` по имени объекта из задачи. Ответ сравни с картой.

**Готово, когда** поиск нашёл те же объекты, что и карта, а каталог `xml\` не изменился. Если Unica не принимает путь вне папки проекта, запиши ответ дословно и оставайся на варианте А.

## В. mcp-1c

Источник: github.com/feenlace/mcp-1c, лицензия MIT у открытой версии. У проекта есть платные редакции: набор предлагает только открытую.

- Основной режим сервера работает через HTTP-сервис 1С и требует поставить в базу расширение. Это меняет базу, поэтому в наборе — только режим по выгрузке: ключ `--dump <путь configDump>\xml`.
- Какие инструменты работают без HTTP-сервиса, узнай по README той версии, которую ставишь, и скажи человеку.
- Подключение к агенту — по README проекта, для Claude Code с `--scope project`, как сервер справки в части 1.

**Готово, когда** сервер подключён и по имени объекта из задачи вернул то же, что карта.

## Г. 1c-mcp-metacode

Источник: github.com/ROCTUP/1c-mcp-metacode, лицензия AGPL-3.0.

- Ставится через Docker Compose по README проекта (раздел «Быстрый старт», `docs/setup.md`). Пароль Neo4j человек задаёт сам в `.env`, ты его не пишешь.
- Данные: сервер читает XML-выгрузку из своего каталога данных (`data/<проект>/code`), источник метаданных — `METADATA_SOURCE=xml`. Как отдать ему выгрузку — копией или подключением каталога, — реши с человеком: в `configDump` сервер писать не должен.
- Поиск по смыслу работает через сервис эмбеддингов (`EMBEDDING_API_BASE`): локальный или внешний. Внешний платный, ключ к нему человек вписывает сам. Без него остаются поиск по метаданным и коду.

**Готово, когда** сервер подключён к агенту и по объекту из задачи вернул то же, что карта.

## Д. Свой индекс

Скрипт пишешь ты, по образцу `map-config.ps1`: новый файл в корне проекта, скрипты набора не правь.

- Читает только выгрузку из `configDump`, базу не открывает.
- Пишет только в `<configDump>\index\`, по текстовому файлу на вопрос, строка на факт: так по нему ищет `rg`.
- Одна команда, без вопросов человеку; код 0 и итоговая строка `Индекс: <файл>, строк N`; пустой индекс — код 1.
- Перестраивается после каждого `dump-config.ps1`.

Пример вопроса: какие документы пишут в регистр. В XML документа (`xml\Documents\<Имя>.xml`) регистры движений перечислены в разделе `RegisterRecords`; строка индекса — `РегистрНакопления.<Имя>: Документ.<Имя1>, Документ.<Имя2>`.

**Готово, когда** индекс построен, а на двух вопросах из задачи человека совпал с тем, что даёт `rg` по выгрузке.
