# Часть 1. Настройка машины

Цель: на машине есть ядро набора, человек выбрал путь проверки кода и справки, инструменты этого пути поставлены, а человек знает, что поставлено, что пропущено и почему.

**Ядро всегда:** платформа 1С, копия базы, git, PowerShell, YAxUnit и скрипты набора `build.ps1`, `build-tests.ps1`, `test.ps1`. *Почему:* итог работы — собранный `.epf` и зелёные тесты, а Unica 0.13 не собирает `.epf` (её `make` собирает только `.cf` и `.cfe`) и не запускает тесты.

**Путь на выбор** — чем проверять код и сверять платформу:
- **«Unica»** — плагин Unica: проверка кода (`unica.check`, стандарт за замечанием — `unica.docs`, разбор — навык `code-diagnostics`), ревью кода, справка платформы, правка метаданных и форм. Только платформа 8.3.27.x;
- **«Свои инструменты»** — BSL Language Server со скриптом `lint.ps1` и сервер справки платформы в Docker;
- **«Своя связка»** — у человека уже есть свои средства (EDT, АПК, свой линтер): агент делает к ним обёртки по правилам набора.

Ход записывай в `setup-log.md` в корне проекта: опись, таблицу, ответы человека, что поставлено. *Почему:* после установки программ агента иногда надо перезапустить, и по журналу ты продолжишь с того же места.

## Правила этой части

- **Задачу человека запиши сразу.** Если в первом сообщении есть задача (например, «сделай новую обработку с функцией …»), до установки чего-либо запиши её дословно в `setup-log.md` разделом `## Задача`. *Почему:* после перезапуска агента первое сообщение в новую сессию не переходит; в прогоне 08.11 задача потерялась, и агент спросил её заново.
- **Ничего не ставь без «да» человека, по одной вещи.** Перед вопросом скажи: что это и зачем, официальный источник, команда, куда ляжет и что поменяется (`PATH`, переменные окружения, настройки агента). «Да» на одну вещь не распространяется на другую.
- **Только официальные источники** из таблиц ниже. Зеркала, сборки третьих лиц и «похожие» пакеты не бери.
- **Платформу 1С и копию базы ставит и готовит человек.** Платформа — по лицензии, копия — из его данных.
- **Вне папки проекта** пиши только туда, куда человек согласился ставить. Переменные окружения пользователя меняй только после «да».
- **Новые программы видны только новым процессам.** После установки git, PowerShell 7 или Docker команда может не находиться, пока агент не перезапущен. Тогда запиши в `setup-log.md`, на каком ты шаге, и попроси человека перезапустить агента со словами «продолжай настройку». Переменные `V8_*` и `BSLLS_EXE` скрипты набора сами берут из настроек пользователя, перезапуск для них не нужен.

## 1.5. Путь «Unica»

BSL Language Server и сервер справки в этом пути не ставь: проверку кода и справку даёт Unica.

### Unica

- **Что даёт** (README проекта): плагин для Claude Code и Codex с навыками и MCP-сервером `unica`. Через инструменты Unica агент создаёт и проверяет метаданные, формы, роли, схемы компоновки данных, внешние обработки и отчёты, выгружает и загружает конфигурацию и расширения, запускает 1С и ищет код. MCP (Model Context Protocol) — протокол подключения инструментов к агенту.
- **Условие:** платформа **8.3.27.x** (README: поддерживается только она), агент — Claude Code или Codex, есть Git for Windows, есть доступ к GitHub.
- **Источник:** github.com/IngvarConsulting/unica, лицензия LGPL-3.0-or-later. В набор не входит, ставится только отсюда.
- **Перед «да» скажи человеку:** плагин включится только в этом проекте и добавит около 5–7 тыс. токенов в каждую сессию здесь (замеры 07 и 08.11); плагин и рантайм (около 55 МБ) лягут в общий кеш `%USERPROFILE%\.claude\plugins\`; рантайм скачается при первом вызове. Если опись показала, что Unica уже стоит, ставить нечего, но всё равно спроси, использовать ли её в этом проекте, и запиши ответ.
- **Установка** — по `guides/unica-windows.md`, раздел 2. Для Claude Code из папки проекта:
  `claude plugin marketplace add IngvarConsulting/unica-marketplace --scope local`, затем `claude plugin install unica@unica --scope local`. Без `--scope local` плагин попадёт во все сессии агента на машине.
  Для Codex — команды из README проекта: `codex plugin marketplace add IngvarConsulting/unica-marketplace --ref main`, затем `codex plugin add unica@unica`; на Codex набор не проверялся.
- **Готово, когда** в новой сессии агента в этой папке вызов `unica.run` с `{}` без запуска 1С вернул словарь операций. Если ответ `delivery_in_progress` — рантайм ещё качается, повтори через минуту. Если новая сессия нужна — запиши ход в `setup-log.md` и попроси человека перезапустить агента со словами «продолжай настройку».

### Проверка пути

1. Файлы проекта Unica — по `guides/unica-windows.md`, раздел 4: `v8project.yaml` (набор `main` с типом `EXTERNAL_DATA_PROCESSORS`, набор расширения тестов), `v8project.local.yaml` с `tools.platform` (и `version`, и `path`), строки `.gitignore`, `.gitattributes`. Пользователя базы впиши из `V8_USER`; пароль, если он есть, впишет человек.
2. `git init` и коммит, если git ещё не заведён.
3. `unica.check` с `{}`. **Готово, когда** `repositoryReady: true`. Полный `ready: true` до части 2 не бывает: Unica отвечает `source_set.path_missing`, пока нет `src\` и `tests\`. Его проверишь в конце части 2.
4. Доставь движок проверки кода: `unica.search` с `role: "symbol"` и любым именем метода (например, `НачалоМесяца`). Ответ `dependencyPending` — норма, повтори через несколько секунд. **Готово, когда** поиск ответил `completed` и есть `bsl-analyzer.exe` в `%USERPROFILE%\.claude\plugins\data\unica-unica\runtimes`. *Почему:* без движка `unica.check` по модулю отвечает `provider_unavailable`, а сам `check` движок не доставляет.

Что из возможностей Unica работает и как ими пользоваться в части 2 — `guides/unica-windows.md`, раздел 7.

### Сервер справки платформы (MCP 1c-syntax)

- **Что даёт:** по запросу агента выдаёт карточку метода или типа из справки той платформы, что стоит у человека: строка вызова, параметры, возвращаемое значение, где можно вызывать (клиент, сервер), версия. Агент сверяет методы по справке, а не по памяти.
- **Условие:** есть Docker с Docker Compose v2, и служба Docker запущена (в описи у Docker есть версия сервера); свободно не меньше 3 ГБ памяти; порт 8000 свободен; есть файл справки `shcntx_ru.hbk` рядом с `1cv8.exe`. Замер автора набора: Elasticsearch занимает 1,7 ГБ, сам сервер 72 МБ; README проекта просит 4 ГБ, это с запасом. При 2–3 ГБ свободных предложи с предупреждением, меньше 2 ГБ — не предлагай. Docker сам не ставь: это решение человека.
- **Источник:** github.com/IElagin/mcp-1c-syntax-assistant, лицензия MIT.
- **Если порт 8000 занят:** проверь `Invoke-RestMethod http://127.0.0.1:8000/health`. Ответ `healthy` — сервер справки уже запущен, установку пропусти и только подключи (п. 5). Другой ответ или ошибка — порт занят чужой программой, спроси человека.
- **Установка** (README и `docs/CLIENT_SETUP.md` проекта), после «да» и в каталог, который назвал человек:
  1. `git clone https://github.com/IElagin/mcp-1c-syntax-assistant.git <каталог>`;
  2. скопировать `shcntx_ru.hbk` из папки платформы в `<каталог>\data\hbk\` (файл справки проприетарный, берётся только из своей установки 1С);
  3. в `<каталог>`: `docker compose up -d`;
  4. ждать, пока `Invoke-RestMethod http://127.0.0.1:8000/health` не вернёт `status` = `healthy`, `indexing_active` = `false`, `documents_count` больше нуля;
  5. Claude Code, из папки проекта: `claude mcp add --transport http --scope project 1c-syntax http://127.0.0.1:8000/mcp` — запись ляжет в `.mcp.json` этого проекта. Codex: в документации сервера команды нет, сверь по `codex mcp add --help`.
- **Если сервер уже подключён к агенту под другим именем** (опись покажет его адрес): второй раз в проект не добавляй без «да» человека, сверяй справку через подключённый.
- **Готово, когда** `claude mcp list` показывает `1c-syntax` со статусом «Connected» (для Codex — по его списку серверов). Сразу после `claude mcp add --scope project` статус «Pending approval» — это нормально: сервер из `.mcp.json` человек подтвердит при следующем запуске агента в папке; до этого сверяй справку через уже подключённый сервер, если он есть.

## 1.7. Путь «Своя связка» (набором не проверялся)

Для человека, который проверяет код и тестирует своими средствами: EDT, АПК, свой линтер, свой запуск тестов.

1. Спроси: чем он проверяет код, чем запускает тесты, как это запустить из командной строки, где взять итог (файл отчёта, код возврата).
2. Для каждого средства сделай в корне свой скрипт-обёртку по образцу `lint.ps1` и `test.ps1`. Скрипты набора не правь, обёртки — новые файлы. Правила обёртки:
   - одна команда, без вопросов человеку;
   - код выхода 0 только при зелёном итоге, иначе 1 (красный), 2 (нет итога), 3 (тайм-аут);
   - итоговая строка в конце: `Замечаний: N` или `ЗЕЛЁНЫЙ` / `КРАСНЫЙ` и `Тестов: N`;
   - пустой результат — не зелёный: нет отчёта или ноль проверок — код 2;
   - оконное приложение — с явным ожиданием и тайм-аутом.
3. Запиши в `setup-log.md`, какие обёртки чем заменяют `lint.ps1` и `test.ps1`. Сборку `.epf` и тесты YAxUnit ядра оставь, если человек не сказал иначе.

**Готово, когда** каждая обёртка дала зелёный итог на нетронутом коде и не зелёный на заведомой ошибке, которую показал человек.
