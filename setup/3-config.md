# Часть 3. Конфигурация

Цель: у агента есть выгрузка конфигурации базы в XML и карта её объектов, а код обработки он пишет только по именам, найденным в выгрузке.

**Когда нужна.** Задача обращается к объектам конфигурации: справочникам, документам, регистрам, перечислениям, общим модулям. Например, «суммы реализаций по контрагентам за период» — это запрос к документу или регистру, и без выгрузки имена пришлось бы угадывать. Начинай после строки `## Часть 2 — готово` в `setup-log.md`. Если задача обходится без объектов конфигурации, часть 3 не нужна.

**Только чтение.** Конфигурацию и расширения базы ты не меняешь. Выгрузку читаешь и ищешь по ней, но не правишь и не удаляешь в ней файлы: каталоги `xml\` и `info\` и файл `map.txt` пишет только `dump-config.ps1`. *Почему:* выгрузка одна на конфигурацию для всех обработок по ней. Тихая правка в ней сломает поиск в других проектах, а в базу из неё ничего не загружается, так что пользы от правки нет.

## 3.1. Где лежит выгрузка

Спроси человека:

1. Есть ли уже выгрузка этой конфигурации от другого проекта по набору. Её путь записан в `settings.json` того проекта, ключ `configDump`. Если есть, бери тот же путь и второй раз не выгружай: переходи к 3.4, а если человек с тех пор обновлял конфигурацию базы, то к обновлению в 3.3.
2. Если нет — в какой каталог её положить. Каталог вне папки проекта, например `D:\1C-dumps\УТ-11.5`: одна выгрузка на конфигурацию, ей пользуются все обработки по этой конфигурации. Скажи человеку, что у типовой конфигурации это десятки тысяч файлов (у УТ 11.5 — около 52 тыс.).

Каталог, который назвал человек в ответ на этот вопрос, — согласие и на полную выгрузку в него (3.3), отдельного «да» не жди. Поэтому, спрашивая каталог, сразу предупреди: полная выгрузка займёт конфигуратор с копией базы на время от минут до десятков минут, сборку и тесты в это время не запускаешь.

После ответа впиши путь в `settings.json` ключом `configDump`, дословно. Скрипт не примет относительный путь и путь внутри папки проекта: в проекте выгрузку подхватили бы git и проверка кода.

**Готово, когда** в `settings.json` есть `configDump`, а ответ человека записан в `setup-log.md`.

## 3.2. Карта объектов

```
pwsh -NoProfile -ExecutionPolicy Bypass -File .\dump-config.ps1 -MapOnly
```

Конфигуратор выгружает только файл версий `ConfigDumpInfo.xml`, без модулей и XML объектов, и скрипт строит по нему карту `<configDump>\map.txt`. В карте каждая строка — объект или группа его частей с русскими именами видов, как в запросах:

```
Документ.РеализацияТоваровУслуг [xml\Documents\РеализацияТоваровУслуг.xml]
Документ.РеализацияТоваровУслуг.Реквизиты: Контрагент, Партнер, ...
Документ.РеализацияТоваровУслуг.ТабличнаяЧасть.Товары.Реквизиты: Номенклатура, Количество, ...
```

Путь к XML в квадратных скобках появляется после полной выгрузки (3.3). Стандартных реквизитов (`Ссылка`, `Дата`, `Номер`, `Проведен`, `Период`, `Регистратор` и других) и типов реквизитов в карте нет: их нет в файле версий.

**Готово, когда** код 0, строка `Карта: …` с числом объектов больше нуля. Если там же строка `ВНИМАНИЕ: в файле версий нет реквизитов` — реквизиты ищи в XML объектов, после 3.3.

## 3.3. Полная выгрузка и обновление

Полная выгрузка нужна, чтобы видеть типы реквизитов, модули, формы и готовые запросы типовой конфигурации. Предупреди человека до запуска, если не сделал этого в 3.1: конфигуратор будет работать с базой из `buildBase` (или `baseCopy`) от минут до десятков минут, пока сборку и тесты не запускаешь; предел ожидания — `configDumpTimeoutMin` в `settings.json`, по умолчанию 120 минут.

```
pwsh -NoProfile -ExecutionPolicy Bypass -File .\dump-config.ps1
```

Если в `configDump` выгрузки ещё нет, скрипт выгружает всё. Если она есть, он её обновляет: конфигуратор выгружает только объекты, изменившиеся с прошлой выгрузки (ключ `-update`), а если обновить нельзя, например сменился формат, — всё заново (`-force`). Потом скрипт перестраивает карту.

**Когда обновлять:** человек сказал, что обновил конфигурацию базы (новый релиз), или версия в первой строке `map.txt` не совпадает с той, что называет человек.

**Готово, когда** код 0, строка `Выгружено (полная)` или `Выгружено (обновление)`, строка `Карта: …`, а у объектов в карте есть пути `[xml\…]`.

| Итог | Что делать |
|---|---|
| Код 2, «есть файлы, но нет ConfigDumpInfo.xml» | Прошлая выгрузка оборвалась или каталог чужой. Ничего не удаляй, к человеку: пусть очистит каталог `xml\` или назовёт другой путь |
| Код 3, тайм-аут | Выгрузка неполная. К человеку: увеличить `configDumpTimeoutMin` и запустить снова после очистки `xml\` |
| Код 1 | Причина в журнале выше. «Пользователь ИБ не идентифицирован» — неверный `v8User` или пароль |

Не запускай выгрузку из двух проектов одновременно: они пишут в один каталог.

## 3.4. Поиск по выгрузке

Ищи своим инструментом поиска (в Claude Code это Grep, он работает на `rg`) или командой `rg`, если опись показала его. Без них — `Select-String` в PowerShell. Модули целиком не открывай, читай кусками до 200 строк вокруг найденного.

Ниже `<D>` — путь из `configDump`.

**Вывод ограничивай.** У типовой конфигурации на одно слово бывают тысячи совпадений, а строка карты с большой группой бывает длиннее 28 тыс. символов: у `Перечисление.ХозяйственныеОперации.Значения` в УТ 11.5 одна строка весит 55 КБ. Такой ответ один съедает заметную часть контекста. Поэтому к каждому поиску по карте добавляй ограничение по строкам и по ширине: в Bash `| head -30 | cut -c1-2000`, в PowerShell `| Select-Object -First 30`. Нужное имя из длинной строки ищи отдельным поиском по самому имени.

| Что найти | Где | Пример |
|---|---|---|
| Есть ли объект, как он называется | `<D>\map.txt` | `rg -n "^РегистрНакопления\.\S*Продаж" <D>\map.txt -m 20` |
| Части объекта: реквизиты, табличные части, измерения, ресурсы | `<D>\map.txt` | `rg -n "^РегистрНакопления\.ВыручкаИСебестоимостьПродаж\." <D>\map.txt` |
| Объект по слову из задачи | `<D>\map.txt` | пример ниже, после таблицы |
| Значения перечисления | `<D>\map.txt` | `rg -n "^Перечисление\.ХозяйственныеОперации\.Значения" <D>\map.txt`, вывод обрезай по ширине |
| Тип реквизита | XML объекта, путь из карты | `rg -n -A 20 "<Name>Контрагент</Name>" <D>\xml\Documents\РеализацияТоваровУслуг.xml`, смотри `<v8:Type>` |
| Какие документы пишут в регистр | XML документов | `rg -l "AccumulationRegister\.ВыручкаИСебестоимостьПродаж" <D>\xml\Documents --max-depth 1` |
| Экспортные методы общего модуля | `<D>\xml\CommonModules\<Имя>\Ext\Module.bsl` | `rg -n -e "^Функция.*Экспорт" -e "^Процедура.*Экспорт" <D>\xml\CommonModules\<Имя>\Ext\Module.bsl` |
| Как типовая уже обращается к объекту | модули `*.bsl` | сначала `rg -l "РегистрНакопления\.ВыручкаИСебестоимостьПродаж" <D>\xml -g "*.bsl"`, потом `rg -n -m 5` в одном-двух файлах из списка |
| Модули объекта и формы | каталог объекта | `xml\Documents\<Имя>\Ext\ObjectModule.bsl`, `ManagerModule.bsl`; форма — `xml\Documents\<Имя>\Forms\<Форма>\Ext\Form.xml` и `...\Ext\Form\Module.bsl` |

Объект по слову из задачи. Ищи только строки объектов основных видов, иначе первые совпадения займут группы реквизитов документов, и до справочника поиск не дойдёт:

```
rg -n -i "^(Справочник|Документ|РегистрНакопления|РегистрСведений|Перечисление)\.\S*контрагент\S* \[" <D>\map.txt
```

В УТ 11.5 это 33 строки, `Справочник.Контрагенты` среди них. Хвост ` \[` ищет строку объекта с путём к XML, а пути есть только после полной выгрузки (3.3). После одного `-MapOnly` вместо него ставь `( \[|$)`.

В XML выгрузки виды объектов записаны по-английски (`AccumulationRegister`, `Document`, `Catalog`), в карте и в коде — по-русски (`РегистрНакопления`, `Документ`, `Справочник`).

Параметры виртуальных таблиц (`Обороты`, `Остатки`, `СрезПоследних`) и методы платформы в выгрузке не ищи: их даёт справка платформы твоего пути, как в части 2.

Без `rg` то же делает `Select-String`. Из Bash вызывай его с префиксом кодировки, иначе кириллица в выводе превратится в кракозябры и в PowerShell 5.1, и в 7:

```
pwsh -NoProfile -Command "[Console]::OutputEncoding=[Text.Encoding]::UTF8; Select-String -Path '<D>\map.txt' -Pattern '^Документ\.Реализация' | Select-Object -First 20"
```

Если `pwsh` нет, вместо него `powershell`.

**Готово, когда** каждый объект задачи (объекты, реквизиты, измерения, ресурсы, значения перечислений, общие модули и их методы) найден в выгрузке, а в `setup-log.md` есть раздел `## Имена из выгрузки`: имя и где найдено (строка карты или файл). Чего не нашёл — спроси человека и запиши его ответ.
